## Installation

`cpd-finder` runs a whole scan. It pulls in the tokenizer, the detection core and the reporters:

```toml [Cargo.toml]
[dependencies]
cpd-finder = "0.1"
```

Or depend on the crates you need:

```toml [Cargo.toml]
[dependencies]
cpd-core = "0.1"
cpd-tokenizer = "0.1"
cpd-reporter = "0.1"
cpd-semantic = "0.1"
```

## Running a scan

```rust [src/main.rs]
use cpd_finder::orchestrate::{RunConfig, run};

fn main() {
    let config = RunConfig {
        paths: vec!["./src".into()],
        min_tokens: 50,
        ..Default::default()
    };

    let result = run(&config).unwrap();
    println!("Found {} clones", result.clones.len());
    println!("Analyzed {} files", result.statistics.total.sources);
}
```

A complete, runnable version is in [`examples/rust-cpd-finder`](https://github.com/kucherenko/jscpd/tree/master/examples/rust-cpd-finder).

## Semantic clones

The `cpd-semantic` crate adds the pass of `--semantic` (experimental) to a run:

```rust
use cpd_finder::orchestrate::{RunConfig, run};
use cpd_semantic::{SemanticOptions, SemanticPass};
use std::sync::Arc;

// The local model is downloaded once, e.g. with `jscpd --semantic-download`.
let options = SemanticOptions::default();
let paths = vec!["./src".into()];
let embedder = cpd_semantic::embedder(&options, &paths, true)?;
// The thresholds of the rules, on the scale of the options' model.
let thresholds = options.thresholds();
let config = RunConfig {
    paths,
    passes: vec![Arc::new(SemanticPass::new(embedder, thresholds, options.scope))],
    ..Default::default()
};
let result = run(&config)?;
```

Unlike the other crates, `cpd-semantic` reads and writes the user cache directory and makes network calls: the model download and the embeddings API. The other crates build without its dependencies.

## Crates

| Crate | What it holds |
|-------|---------------|
| [`cpd-core`](https://crates.io/crates/cpd-core) | Data models and the Rabin-Karp rolling hash |
| [`cpd-tokenizer`](https://crates.io/crates/cpd-tokenizer) | Tokenization of 224 formats: the oxc parser for JavaScript and TypeScript, the ruff parser for the Python functions of `--similarity`, and generic rules for the other formats. Pure, with no file or network access |
| [`cpd-finder`](https://crates.io/crates/cpd-finder) | File walking, orchestration and git blame |
| [`cpd-reporter`](https://crates.io/crates/cpd-reporter) | The 15 reporters: console, console-full, json, xml, csv, html, markdown, sarif, openmetrics, codeclimate, ai, badge, xcode, threshold, silent |
| [`cpd-semantic`](https://crates.io/crates/cpd-semantic) | Semantic clones (`--semantic`, experimental), as a clone pass for `cpd-finder` |

The library target of the `jscpd` crate is not a public API. It shares helpers with the crate's tests and may change in any release, so depend on the crates above.

## Features

- Pure Rust, with no external runtime
- Parallel detection across format groups with `rayon`
- The oxc parser for JavaScript, TypeScript, JSX and TSX, and ruff for Python functions
- Git blame enrichment: per-line author data from `git blame --porcelain`
- Cross-format detection for Vue SFC, Svelte, Astro and Markdown

Coming from the v4 `@jscpd/*` npm packages? The [Migration Guide](/getting-started/migration) maps each one to its Rust crate.
