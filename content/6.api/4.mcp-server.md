## Overview

jscpd implements the [Model Context Protocol (MCP)](https://modelcontextprotocol.io/), so AI assistants such as Claude Desktop, Claude Code, Cursor and Copilot can look for duplicated code from the editor without running the CLI. The server is built into the binary (v5.0.16+) and speaks MCP over stdio. The client starts and manages the process, so you need no port, no network policy and no extra package.

With the server, an assistant can:

- check code it is about to write for exact, renamed, near-miss and semantic copies in the project (`check_duplication`)
- list the clones of a file before it refactors that file (`get_file_clones`)
- read the duplication statistics (`get_statistics`), and scan again after it edits files (`check_current_directory`)
- compare two folders function by function, such as a port and its original (`compare_folders`)

## Start the server

```bash [Terminal]
jscpd --mcp /path/to/project

# The detection options apply to the scan and to snippet checks:
jscpd --mcp --min-tokens 30 --format javascript,typescript /path/to/project

# Look for the first three types of clone in every call:
jscpd --mcp --kind exact,renamed,similar /path/to/project
```

Add the server to your MCP client's config (Claude Desktop, Claude Code, Cursor, ...):

```json
{
  "mcpServers": {
    "jscpd": {
      "command": "jscpd",
      "args": ["--mcp", "/path/to/project"]
    }
  }
}
```

The server scans the project in the background as it starts, so the client connects at once. The first tool call waits for the scan. A line on stderr says when the scan is done, and only protocol messages go to stdout. Snippet checks compare against the tokens the server keeps in memory and need no new scan.

## Clone types

The tools find the four types of clone that the [clone types guide](/guides/clone-types) describes:

| Kind | Type | What it is | How the server finds it |
|------|------|------------|-------------------------|
| `exact` | Type-1 | The same tokens; layout and comments may differ | The token passes of the scan |
| `renamed` | Type-2 | The same code with identifiers or literals changed | The normalization the options configure (`--ignore-identifiers`, `--ignore-literals`, `--ignore-annotations`); with none configured, a second scan that normalizes identifiers and literals |
| `similar` | Type-3 | A copy with lines added, removed or changed | `gap`: clones of one file pair merged across up to `--max-gap-lines` unmatched lines (2 when the option is not set). `ast`: JavaScript and TypeScript functions with the same syntax-tree shape, at `--similarity` (0.85 when not set) |
| `semantic` | Type-4 | Functions that do the same job, written differently or in another language | The `--semantic` embedding model, see [Semantic Clones](/guides/semantic-clones) |

Every clone tool takes `kinds`, a list of kind names. `gap` and `ast` name one of the two ways to find similar clones, and `type1` to `type4` work as names too. Without `kinds`, a tool reports what `jscpd` reports with the server's options. By default that means exact clones, plus renamed ones when `--ignore-identifiers`, `--ignore-literals` or `--ignore-annotations` is on, similar ones with `--max-gap-lines` or `--similarity`, and semantic ones with `--semantic` or the config's `semantic.enabled`. `--kind` sets other defaults, so `jscpd --mcp --kind exact,renamed,similar` looks for the first three types in every call.

The server finds a kind the first time a request asks for it and keeps the result until `check_current_directory` scans again. A request without `renamed` reads the scan made with the configured options, so its exact clones match a `jscpd` run with the same options. Ast and semantic clones need the syntax trees and functions of the files, and a scan reads them from the same text as its tokens. The first request for one of these kinds may therefore scan again, and every result describes the same files.

Semantic clones need the embedding model on this machine or an embeddings API (`--semantic-url`). Download the model once with `jscpd --semantic-download` (548 MB). The server never downloads it. When it cannot look for semantic clones, the result lists `semantic` under `unavailable` with the reason, and the assistant can ask you first. The first semantic request embeds every function of the project, which can take minutes. Later requests reuse the vectors cached for the project, and `jscpd --semantic` on the same folder uses that cache too.

## Tools

### `check_duplication`

Compares a snippet with the scanned project, so the assistant can reuse existing code instead of writing it again.

| Argument | Type | Description |
|----------|------|-------------|
| `code` | string, required | The code to check, verbatim. Whole functions or blocks work best. |
| `format` | string, required | A format name (`javascript`) or a file extension (`js`) |
| `kinds` | array | The kinds of clone to look for |
| `similarity` | number | The threshold of ast matches for this call, a ratio in `(0, 1]`; `1` turns them off |
| `limit` | number | The most matches to return (default 100) |

A match has its `kind`, the file and lines of the project's copy and of the snippet's, and `tokens`. Similar and semantic matches add `similarity`, similar ones also `method` (`gap` or `ast`), and a match between two functions adds `name` (the project's function) and `snippetName`. Exact matches come first, then renamed, similar and semantic ones. A snippet shorter than `--min-tokens` cannot match and gets a `note` that says so.

This is the answer for a Python version of the cart totals in jscpd's [semantic demo](https://github.com/kucherenko/jscpd/tree/master/fixtures/semantic-demo), asked with `"kinds": ["semantic"]`. The demo has the function in Rust and again in Svelte:

```json
{
  "count": 2,
  "duplications": [
    {
      "file": "backend/src/pricing.rs",
      "fileEndLine": 58,
      "fileStartLine": 34,
      "kind": "semantic",
      "name": "cart_totals",
      "similarity": 0.889,
      "snippetEndLine": 12,
      "snippetName": "cart_totals",
      "snippetStartLine": 1,
      "tokens": 111
    },
    {
      "file": "frontend/src/lib/components/CartSummary.svelte",
      "fileEndLine": 31,
      "fileStartLine": 19,
      "kind": "semantic",
      "name": "computeTotals",
      "similarity": 0.75,
      "snippetEndLine": 12,
      "snippetName": "cart_totals",
      "snippetStartLine": 1,
      "tokens": 111
    }
  ],
  "format": "python",
  "kinds": ["semantic"],
  "returned": 2
}
```

A request without `kinds` gets its ast matches under `similar` with `similarCount`, plus `similarNote` for a language without syntax trees, the way earlier versions answered. With `kinds`, every match is in `duplications`.

### `get_file_clones`

Lists the clones of one file, for refactoring that file.

| Argument | Type | Description |
|----------|------|-------------|
| `path` | string, required | The file, relative to the scan root as results show paths, or absolute |
| `kinds` | array | The kinds of clone to look for |
| `limit` | number | The most clones to return (default 100) |

Each clone has its `kind`, `format`, both files with their first and last lines (`fileA`, `startA`, `endA`, `fileB`, `startB`, `endB`), `lines` and `tokens`. The file you ask about can be either side. `byKind` counts the clones of each kind, and a file the scan did not include gets `clones: 0` and a `note`. In the [mcp-demo](#try-it-from-a-shell), the copy of an invoice with one added line comes back as one clone, merged across the gap:

```json
{
  "byKind": { "gap": 1 },
  "clones": 1,
  "duplications": [
    {
      "endA": 12,
      "endB": 13,
      "fileA": "src/invoice.js",
      "fileB": "src/print/invoice.js",
      "format": "javascript",
      "kind": "similar",
      "lines": 12,
      "method": "gap",
      "similarity": 0.947,
      "startA": 1,
      "startB": 1,
      "tokens": 197
    }
  ],
  "file": "src/print/invoice.js",
  "kinds": ["exact", "renamed", "similar"],
  "returned": 1
}
```

### `get_statistics`

Returns the duplication statistics of the last scan for the kinds asked: files, lines and tokens, clones, and the duplicated lines and tokens with their percentages, for the whole project and per format. `byKind` counts the clones of each kind.

| Argument | Type | Description |
|----------|------|-------------|
| `kinds` | array | The kinds of clone to count |

### `check_current_directory`

Scans the configured paths again and returns the new counts and clone list, with the clones in the shape `get_file_clones` uses. Call it after the assistant edits files, so the other tools answer from the files as they are now.

| Argument | Type | Description |
|----------|------|-------------|
| `kinds` | array | The kinds of clone to look for |
| `limit` | number | The most clones to return (default 100) |

### `compare_folders`

Compares two folders function by function, in one language or across two, as [`jscpd --compare`](/guides/compare) does. Use it for a port and its original, or for the iOS and Android versions of an app. It returns the JSON report of `--compare`, with a `code` and a `tests` section, plus the name of the model.

| Argument | Type | Description |
|----------|------|-------------|
| `left` | string, required | The first folder: the source of a port, or one of two implementations |
| `right` | string, required | The second folder: the target of a port, or the other implementation |
| `limit` | number | The most entries in each list of the report (default 100) |

Both folders must lie inside the paths the server scans, and a relative path starts from one of them. To compare two projects, start the server with both. `compare_folders` needs the embedding model, like semantic clones. The first comparison of two folders embeds every function, and later ones reuse the cached vectors.

## Results and errors

A tool answers with JSON, sent as `structuredContent` and again as text for clients of older revisions. Clone lists come biggest first, except the matches of `check_duplication`, which keep the order above. The optional `limit` argument caps every list, at 100 entries by default. The count next to a list (`clones`, `count`) always gives the full number, and a cut list carries a `note`.

If a tool cannot use its arguments, such as a missing `code`, an unknown format or kind, or a `similarity` out of range, the server answers with a tool error (`isError: true`), a message that says what to fix, so the assistant can try again. An unknown tool gets a JSON-RPC error. The tools are read-only and never change the project's files.

## Protocol revisions

The server speaks MCP 2026-07-28, the stateless revision, in which each request names its version in `_meta` and `server/discover` describes the server. It also speaks the revisions that open with an `initialize` handshake (2025-11-25, 2025-06-18, 2025-03-26 and 2024-11-05), and one process serves clients of both kinds.

## Try it from a shell

The [`mcp-demo`](https://github.com/kucherenko/jscpd/tree/master/fixtures/mcp-demo) folder in the jscpd repository holds one pair of files for each kind the token passes find. Its README sends requests to the server one line at a time, the way an assistant does, and lists the answer to each.

## Tips

- Pass the same detection flags you use on the CLI (`--min-tokens`, `--format`, `--ignore`, ...), so the default results match your CI runs.
- Use `--kind` to choose what every call looks for when it gives no `kinds`.
- Keep the model downloaded if you want semantic clones and `compare_folders`; without it, the other kinds still work.

> Looking for the Node.js HTTP server (`jscpd-server`, REST API + MCP over HTTP)? It belongs to v4 and is documented on the [`master-v4` branch](https://github.com/kucherenko/jscpd/tree/master-v4) and the [v4 page](/getting-started/v4).
