A copied function rarely stays an exact copy. Its variables get new names, a constant changes, a log line goes in, and the token passes of jscpd lose it, because they need a long run of tokens that repeats. `--similarity` compares whole functions by the structure of their syntax trees instead. It finds a copy with other names and other literals, and a copy with a statement or two added or changed, and reports the pair as a clone of kind `similar` with the method `ast`. These are [Type-3 near-miss clones](/concepts/clone-types#type-3-near-miss-clones).

::note
This page describes `--similarity` from the release after 5.4.0. Up to 5.4.0 it compared JavaScript and TypeScript functions only, by the sequence of their node types, and scored more loosely, so a pair that scored `0.85` there can score lower now. Refresh a baseline or a `--threshold` that was set on the old results.
::

## Quick start

```bash [Terminal]
jscpd --similarity src/            # pairs that score 0.8 or more
jscpd --similarity 0.7 src/        # looser: a couple of added or removed statements
jscpd --similarity -r edn src/     # every pair with its score, in report/jscpd-report.edn
```

A pair shows up in the same report as the token clones:

```text
Clone found (python, similar (ast) ~1.00)
 - insurance.py [1:1 - 8:26] (8 lines, 62 tokens)
   shipping.py [1:1 - 8:29]
```

`shipping.py` prices a parcel and `insurance.py` prices a policy. Every name and every number differs, so no run of tokens repeats, but the two functions call the same functions in the same order. To try it, run it on [`fixtures/similarity-demo`](https://github.com/kucherenko/jscpd/tree/master/fixtures/similarity-demo): a renamed copy, a copy that calls other methods, an edited copy, copies in Markdown code blocks and in test files, and one pair for each language.

## How it works

`--similarity` takes four steps. It picks the functions, normalizes the syntax tree of each one, turns the tree into a set of fingerprints, and searches for the pairs whose sets overlap enough.

### Which code is compared

jscpd parses each file with its tree-sitter grammar, and Clojure with a reader of its own. A unit is a function or a method, and what counts as one depends on the language:

| Language | Units |
|---|---|
| Python | Functions and methods. A function in a function is part of it; a method of a class declared in a function is a unit of its own. A stub, whose body is a docstring and `...` only, as an `@overload` signature or a `Protocol` member has, is none. |
| JavaScript, TypeScript | Functions, generators and methods outside every function, with the variable or field a function is assigned to there, and the functions passed as callbacks, assigned to `exports` or a prototype, or held by an object literal at the top of a module. Callbacks inside a function are part of it. A function that only wraps a module, an immediately invoked one or the factory of a UMD or AMD module, is no unit, and the functions in it are units. |
| Java | Methods with a body, not constructors and not the methods of classes declared in a method. |
| Kotlin, Scala, C#, PHP, Swift | Functions and methods with a body outside every function. Constructors are left out. |
| C, C++ | Function definitions outside every function, read with the C++ grammar, so a C function and its copy in a header or a `.cpp` file read alike. Lambdas are part of the function around them. |
| Ruby | Methods, `def self.` ones too, outside every method. |
| Go | Functions and methods with a body. |
| Rust | Functions with a body, not those in a function, in a `mod tests` or a module under `#[cfg(test)]`, or marked `#[test]` or `#[tokio::test]`. |
| Clojure | Every top-level form except `ns`, read with the `:clj` branch of reader conditionals and the `#+clj` forms of `.cljx` files. A form keeps its own lines inside a reader conditional and ends where its last part ends. |

The code blocks of Markdown files and the scripts of Vue, Svelte and Astro files count too. Each block is parsed in its own language, and a pair there is reported at the lines of the host file, as in `guide.md:python [7:1 - 14:28]`. Units pair only within one language, except that JavaScript pairs with TypeScript and C with C++.

Test files are left out, by the conventions of each language: `test_*.py`, `*_test.go`, `*.test.ts`, a `tests/` or `__tests__/` folder and the like. jscpd reads the path below the scanned folder, so a project that lives in a folder named `tests` is still compared. Python's `.pyi` stubs and Clojure's `.edn` data are not read. PHP code without a `<?php` tag, as in a Markdown block or a snippet, is read as PHP.

### Normalizing the tree

The syntax tree of a unit becomes a nested list, and every node is a list headed by its type. The names of the functions and methods the unit calls keep their spelling, and so do its operators. Every other name, a local, a parameter or a field, becomes `:symbol`, and every literal becomes `:literal`. Comments and punctuation drop out, and so do parentheses around a single expression. This function:

```python
def price(parcel, rates):
    weight = parcel.weight * 1.2
    return max(lookup(rates, weight), 5)
```

becomes:

```clojure
[:function_definition :symbol [:parameters :symbol :symbol]
 [:block
  [:assignment :symbol [:symbol "="]
   [:binary_operator [:attribute :symbol :symbol] [:symbol "*"] :literal]]
  [:return_statement
   [:call [:symbol "max"]
    [:argument_list
     [:call [:symbol "lookup"] [:argument_list :symbol :symbol]]
     :literal]]]]]
```

`price`, `parcel`, `rates` and `weight` all read as `:symbol`, and `1.2` and `5` as `:literal`, while `max`, `lookup`, `*` and `=` keep their spelling. A function that prices a policy with other names and other numbers turns into the same list.

Called names and operators count on purpose. `filter(is_paid, orders)` and `remove(is_paid, orders)` have one shape and do opposite things, and so do `total + fee` and `total - fee`.

### Fingerprints and the score

Every list in the normalized tree, written out as text, is a fingerprint, and so is every atom such as `:literal` or `[:symbol "max"]`. The function above has 44 nodes and 30 distinct fingerprints: the whole function, its block, each statement, each call, and so on down to the atoms.

Two functions score the Jaccard index of their fingerprint sets: the number of fingerprints they share divided by the number that either of them has. The same structure scores `1.0`. An edit changes the list that holds it and every list around it up to the function itself, so it costs a few fingerprints at once. This is what one edit does to a function of ten lines and 115 nodes:

| Edit | Score |
|---|---|
| Other names and other literals | 1.00 |
| Parentheses around an expression, comments | 1.00 |
| Two statements swapped | 0.93 |
| One call statement added | 0.89 |
| One operator changed, `*` to `+` | 0.78 |
| One `if` block removed | 0.78 |
| One called function changed, `lookup` to `fetch_rate` | 0.75 |

A bigger function loses less from one edit, because the edit is a smaller share of its subtrees.

### The search

The search is exact: it finds every pair whose score reaches the threshold, with no sampling. jscpd ranks the fingerprints of all units from the rarest to the most common and indexes each unit by its rarest few. Two sets whose Jaccard index reaches `t` must share one of the first `n - ceil(t × n) + 1` fingerprints of a set of size `n`, so jscpd compares only the pairs that do, and it skips the pairs whose sizes are too far apart to reach `t`. Most pairs are never compared, functions with the same fingerprints are compared once, and every candidate gets its exact score.

A group of look-alike functions is reported as the pairs that link it, each function with its closest match, the way detection pairs every copy of a fragment with the first one: ten copies of one getter are nine clones, not forty-five. Functions that an exact, renamed or merged clone already connects are not linked again, and a function never pairs with one nested inside it. The `edn` report still lists every pair.

### Size limits

A unit needs at least `--min-nodes` nodes in its normalized tree, 20 by default, and it must span at least `--min-lines` lines. Small functions match too easily, since any two getters have one shape. `--min-tokens` does not apply to units. Code that the token passes skip does not count either: what lies between `jscpd:ignore-start` and `jscpd:ignore-end` or matches `--ignore-pattern` adds nothing to a unit's tree, and a unit inside such code is not compared.

## Thresholds

The ratio after `--similarity` is the lowest score that gets reported, a number in `(0, 1]`. Without one it is the config's `similarity`, else `0.8`. The ratio can follow the flag after a space or after `=`, and a path after the bare flag stays a path:

```bash [Terminal]
jscpd --similarity src/          # 0.8: renames, other literals, a one-line edit
jscpd --similarity 0.7 src/      # looser: a couple of added or removed statements
jscpd --similarity=1 src/        # the same structure only
```

`0.8` keeps a renamed copy and a copy with one statement added or swapped. In a short function it drops a copy that calls another function or uses another operator. In [`fixtures/type3-demo/similar-functions`](https://github.com/kucherenko/jscpd/tree/master/fixtures/type3-demo/similar-functions), a copy with every name changed, a guard and a logging call added, and one other function called scores `0.67`, so it takes `--similarity 0.6` to see it. A ratio outside `(0, 1]` prints a warning and turns the search off. Up to 5.4.0 a ratio of `1` turned the search off; now it asks for the same structure only, and jscpd warns about the change, so leave the option out to keep the search off.

To see what a lower ratio would add before you change it, run the `edn` reporter at the lower ratio and read the scores between the two.

## Options

| Flag | Config key | What it does | Default |
|---|---|---|---|
| `--similarity[=RATIO]` | `similarity` | Turns the search on. RATIO is the lowest score reported, a number in `(0, 1]` | off; with no value the config's ratio, else `0.8` |
| `--min-nodes <N>` | `minNodes` | The fewest nodes a unit's normalized tree needs to be compared | `20` |
| `--min-lines <N>` | `minLines` | The fewest lines a unit spans, as for token clones | `5` |
| `--kind <LIST>` | `kind` | Keeps only some kinds of clones: `ast` for these pairs, `similar` for them and the merges of `--max-gap-lines` | every kind |
| `--reporters edn` | `reporters` | Writes every pair with its score to `jscpd-report.edn` | |

`--ignore`, `--ignore-pattern` and `--format` choose the code as they do for token clones, and `--skip-local` and `--skip-isolated` drop function pairs as they drop token clones. In a config file:

```json [.jscpd.json]
{
  "similarity": 0.8,
  "minNodes": 20,
  "reporters": ["console", "edn"],
  "output": ".metrics"
}
```

## Output

Every reporter shows these pairs next to the token clones, as clones of kind `similar` with the method `ast`:

- The console prints `Clone found (python, similar (ast) ~0.85)`, and the `ai` reporter `[~0.85 ast]`.
- JSON has `"kind": "similar"`, `"method": "ast"`, the score as `"similarity"`, and the size of each normalized tree as `"nodes"` in `firstFile` and `secondFile`.
- SARIF and Code Climate file the pairs under the rule `jscpd/similar-function`, apart from the merges of `--max-gap-lines` under `jscpd/similar-code`. SARIF adds `similarity_method` and `nodes`.
- `tokens` is the token count of the smaller function, and the fragments span the whole functions.

### The edn report

`-r edn` writes `jscpd-report.edn` in [EDN](https://github.com/edn-format/edn), the data notation of Clojure. It lists every pair the search found under `:candidates`, the pairs that a token clone covers and the ones a group's links imply too, most similar first, and the clones of the other passes under `:clones`:

```clojure [jscpd-report.edn]
{:candidates [
 {:score 0.890909090909
  :language "python"
  :left {:file "src/billing/invoice.py", :start-line 3, :end-line 13}
  :right {:file "src/billing/receipt.py", :start-line 3, :end-line 14}
  :left-nodes 158
  :right-nodes 166}
]
 :clones [
 {:kind :exact
  :format "go"
  :left {:file "src/a.go", :start-line 1, :end-line 11}
  :right {:file "src/b.go", :start-line 1, :end-line 11}
  :tokens 55}
]}
```

`:score` is the Jaccard index with up to 12 decimals, and `:left-nodes` and `:right-nodes` are the sizes of the two normalized trees. Pairs with the same score are sorted by language, file and line, so two runs on the same code write the same file. A function in a Markdown code block or a component is named by its host file. A run with no pairs writes `{:candidates []` and an empty `:clones []`. `jscpd --similarity -r console,edn -o .metrics` puts the file at `.metrics/jscpd-report.edn` and still prints the console report.

## In editors and agents

- The [language server](/guides/editors) shows the pairs with its `ast` analysis, as one information diagnostic on the first line of each function: `Same structure as the function at src/holds.js:13-20 (1.00)`. `ast.similarity` sets the ratio, `0.8` unless the config's `similarity` key sets another, and `minNodes` in the project's config sets the size limit.
- The [MCP server](/guides/agents) finds the pairs when a tool call asks for the kinds `ast`, `similar` or `type3`, at `0.8` unless `--similarity` sets another ratio. Its `check_duplication` tool takes a `similarity` argument for the functions of a snippet.

## What it does not do

- It does not pair functions of two languages, except JavaScript with TypeScript and C with C++. For code ported from one language to another, use [`--compare`](/guides/compare) or [`--semantic`](/guides/semantic-clones).
- It does not find functions that do the same job with different code. The structure has to match; [semantic clones](/guides/semantic-clones) cover the rest.
- It does not compare classes, modules or top-level code. A function nested in another one is part of it.
- It does not read test files.
