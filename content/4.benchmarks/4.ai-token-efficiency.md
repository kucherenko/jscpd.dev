When CPD output is fed to an LLM (for automated refactoring, code review, or deduplication workflows), output size directly impacts cost, latency, and context window usage. jscpd's `--reporters ai` flag is purpose-built for this — agents and LLM workflows should use it by default.

## The AI Reporter

The `--reporters ai` flag produces a token-efficient plain-text format designed for LLM consumption. Key optimizations:

- **Common-path-prefix compression** — shared directory prefixes are factored out (e.g., `fixtures/clike/ file1.cpp:1-88 ~ file2.cpp:1-88` instead of two full paths)
- **No code fragments** — only file paths and line ranges are reported
- **Minimal structure** — one line per clone, no JSON overhead
- **Summary line** — clone count and duplication percentage after a `---` separator

The AI reporter uses **~2,800 tokens** for 212 clones (13 tokens/clone) — an **8× reduction** versus the console reporter (~23,000 tokens, 110 tokens/clone).

Sample output:

```text
fixtures/clike/ file1.cpp:1-88 ~ file2.cpp:1-88
fixtures/clike/ file1.cs:1-91 ~ file2.cs:1-91
fixtures/svelte/ component1.svelte:css:112-230 ~ component2.svelte:css:112-230
fixtures/markdown/ file3.md:typescript:34-64 ~ file4.md:typescript:34-64
---
212 clones · 37.1% duplication
```

## Methodology

- **Target:** `fixtures/` directory — 547 files, 21,645 lines across 150+ language formats
- **Token estimation:** Using `cl100k_base` tokenizer on each tool's default output
- **Output formats:** Each tool's primary output format (AI reporter, console, JSON, plain text)
- **Hardware:** Apple Silicon (Darwin arm64)

Full methodology details are in the [jscpd repository](https://github.com/kucherenko/jscpd/blob/master/benchmark/BENCHMARK.md).
