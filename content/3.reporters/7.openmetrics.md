## Overview

The `openmetrics` reporter writes `jscpd-metrics.txt` in the [OpenMetrics](https://openmetrics.io/) text exposition format. Declare it as a GitLab CI `artifacts:reports:metrics` artifact and merge requests show how duplication metrics changed against the target branch.

Available since **v5.1.0**.

## Usage

```bash
jscpd --reporters openmetrics ./src
```

Output file: `./report/jscpd-metrics.txt`

## Exposed Metrics

| Gauge | Description |
|-------|-------------|
| `jscpd_files_analyzed` | Number of files scanned |
| `jscpd_lines_analyzed` | Total lines scanned |
| `jscpd_tokens_analyzed` | Total tokens scanned |
| `jscpd_clones_found` | Clone pairs found |
| `jscpd_duplicated_lines` | Duplicated lines (plus a percentage gauge) |
| `jscpd_duplicated_tokens` | Duplicated tokens (plus a percentage gauge) |
| `jscpd_new_clones` / `jscpd_new_duplicated_lines` | New duplication when a [baseline](/ci-and-hooks/ci#gate-on-new-duplication-baseline) is configured |
| `jscpd_detection_duration_seconds` | Detection time |

Project totals come first; per-format samples carry a `format` label.

## GitLab CI Integration

```yaml [.gitlab-ci.yml]
jscpd:
  stage: test
  image: node:22
  before_script:
    - npm install -g jscpd@5
  script:
    - jscpd --reporters console,openmetrics --output report .
  artifacts:
    reports:
      metrics: report/jscpd-metrics.txt
```

The merge request's **Metrics** section then shows each gauge with its delta against the target branch.

## Configuration

```json [.jscpd.json]
{
  "reporters": ["openmetrics"],
  "output": "./report"
}
```
