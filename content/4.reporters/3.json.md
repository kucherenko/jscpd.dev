## Usage

```bash
jscpd --reporters json ./src
```

## Output

The JSON reporter generates a `jscpd-report.json` file with structured data:

```json
{
  "duplicates": [
    {
      "format": "javascript",
      "lines": 10,
      "tokens": 120,
      "firstFile": {
        "name": "src/utils.js",
        "start": 10,
        "end": 20
      },
      "secondFile": {
        "name": "src/helpers.js",
        "start": 5,
        "end": 15
      }
    }
  ],
  "statistics": {
    "total": {
      "lines": 1000,
      "tokens": 15000,
      "sources": 50,
      "clones": 5,
      "duplicatedLines": 50,
      "percentage": 5.0
    }
  }
}
```

Each duplicate also carries its `kind`: `exact`, `renamed`, `similar` or `semantic` (see [Types of Code Clones](/guides/clone-types)). A `similar` or `semantic` clone adds its score as `similarity`, and a `similar` one adds `method`, `gap` for a copy merged across edited lines or `ast` for a pair of functions from `--similarity`. The real report also holds the copied `fragment`, `startLoc` and `endLoc` with columns, `isNew` for a run with a baseline, and the statistics of each format.

## CI/CD Integration

Use JSON output for automated pipelines:

```yaml [.github/workflows/jscpd.yml]
- name: Check for duplicates
  run: |
    jscpd --reporters json --threshold 5 ./src
    cat report/jscpd-report.json
```
